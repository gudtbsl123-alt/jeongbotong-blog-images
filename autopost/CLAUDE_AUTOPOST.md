# 오카와리 업로드 대기열 규칙 (클로드 코드용)

카드뉴스·릴스·블로그 원고를 다 만든 뒤 아래 형식으로 **대기열**에 넣는다.
실제 게시는 GitHub Actions(인스타)와 Aside(블로그 임시저장)가 한다. 클로드 코드는 직접 게시하지 않는다.

---

## 1. 인스타 대기열 — `autopost/ig_queue/`

카드·릴스 파일은 지금처럼 `posting/<slug>/` 에 올린다 (01~08.jpg, reel.mp4, reel_cover.jpg).
대기열에는 **어느 posting 폴더를 언제 올릴지**만 적는다. 파일을 복사하지 않는다 (저장소가 이미 1GB를 넘음).

**게시물 하나 = 대기열 폴더 하나.** 이름: `YYYYMMDD-HHMM-<slug>-card` 또는 `-reel` (예: `20261123-1910-1118-fukuoka-ramen2-roundup-reel`).
한글·띄어쓰기·대문자는 쓰지 않는다. `_` 로 시작하는 폴더는 게시되지 않는다.

폴더 안에는 `post.json` 과 `caption.txt` 두 개만.

```json
{ "type": "carousel", "source": "posting/1118-fukuoka-ramen2-roundup", "publish_at": "2026-11-23 19:10" }
{ "type": "reel", "source": "posting/1118-fukuoka-ramen2-roundup", "publish_at": "2026-11-24 12:40" }
```
- `source`: 저장소 맨 위 기준 posting 폴더.
  - 카드뉴스: 그 폴더의 사진을 이름순으로 2~10장 올린다 (`reel_cover`, `story*`, `cover` 는 자동 제외).
  - 릴스: 그 폴더의 영상(`reel.mp4`)을 올리고, `reel_cover.jpg` 가 있으면 표지로 쓴다.
  - 특정 파일만 쓰려면 `"media": ["01.jpg", "03.jpg", "05.jpg"]` 처럼 순서대로 적는다.
- `publish_at`: **한국 시간**. 같은 시각에 2개 이상 넣지 않는다 (겹치면 30분씩 밀려 올라감).
- 선택 항목: `collaborators` (공동 게시 아이디 최대 3개, 예 `["shop_id"]`), `thumb_offset_ms` (표지 없을 때 표지로 쓸 지점), `share_to_feed` (릴스를 피드에도, 기본 true).
- `caption.txt`: UTF-8, 2,200자·해시태그 30개 이하. 캡션 글쓰기 기준은 기존 카드뉴스 규칙을 따른다.

파일 규격 (지금 posting 파일들은 모두 맞음)
- 카드: **1080×1350 JPEG** (캐러셀은 모든 장이 첫 장 비율로 잘림)
- 릴스: 1080×1920, H.264 + AAC, 30fps, 3초~15분, **100MB 미만**. ffmpeg 출력에 `-movflags +faststart`

넣은 다음 반드시 (jeongbotong-blog-images 저장소에서)
```bash
python autopost/ig/ig_publish.py prepare autopost/ig_queue/<폴더>
```
- `[오류]` 가 나오면 고치고 다시. `[OK]` 가 나와야 끝.
- 그다음 `git pull --rebase` → `git add` → `git commit` → `git push` (봇이 게시 기록을 커밋하므로 pull 먼저).
- posting 파일과 대기열 폴더는 같은 push에 넣는 게 좋다.

게시 뒤 대기열 폴더에 생기는 파일
- `published.json` — 게시 완료 (인스타 주소). 이 폴더는 다시 건드리지 않는다.
- `error.json` — 실패 이유. 읽고 고친 뒤 **error.json을 지우고** push 하면 다음 실행에서 다시 시도.
- `pending.json` — 메타가 영상 처리 중. 건드리지 않는다.

## 2. 블로그 대기열 — `autopost/blog_queue/`

폴더 이름: `YYYYMMDD-영문슬러그`. **하루 1개.** Aside가 이름순으로 하나씩 임시저장한다.

폴더 안
- `blog.md` — 원고 (형식은 `_example/blog.md`)
- `memo.txt` — 사용자가 직접 적은 경험 메모 (있을 때만)
- `01.jpg` … — 본문 사진. **카드 이미지(글자 들어간 것) 말고 원본 사진**을 쓴다.

`blog.md` 형식
```
제목: ...
카테고리: ...        ← 참고용 (발행할 때 사용자가 직접 선택)
태그: a, b, c        ← 참고용
---
본문 문단

[사진 01.jpg]

## 소제목

[장소 가게 정식 이름]

[✍️ 직접: ...]
```
- 본문은 마크다운 꾸밈(굵게, 링크, 표)을 쓰지 않는다. 쓰는 표시는 `## `, `[사진 파일]`, `[장소 이름]`, `[✍️ ...]` 네 가지뿐.

### 블로그 글쓰기 기준 (사람이 쓴 글로 읽히게)
1. **경험을 지어내지 않는다.** "제가 가 보니", "먹어 보니" 같은 1인칭 경험은 `memo.txt` 에 있는 것만 쓴다.
   메모가 없거나 모자라면 경험이 들어갈 자리에 `[✍️ 직접: 무엇을 시켰고 어땠는지 한 줄]` 을 2~3곳 남긴다.
2. **인스타 캡션을 복사하거나 늘려 쓰지 않는다.** 같은 소재라도 블로그용으로 새로 쓴다 (같은 문장 재사용 금지).
3. **구체적으로 쓴다.** 가격(엔, 확인한 날짜), 영업시간·쉬는 날, 가까운 역·출구·도보 시간, 줄 서는 요령.
   확인하지 못한 정보는 쓰지 않는다.
4. **말투는 기존 블로그 글처럼** 편한 존댓말. 짧은 문장과 긴 문장을 섞는다.
5. **피할 표현**: "~에 대해 알아보겠습니다", "결론적으로", "다양한", "완벽한", "~하는 것이 중요합니다",
   "꼭 방문해 보세요!", 문단마다 이모지, 모든 목록을 3개로 맞추기, 소제목 기계적 나열, 끝의 '총정리' 문단.
6. **구성**: 첫 문단은 이 가게를 고른 이유나 장면 하나 → 메뉴와 맛 → 가는 법·팁 → 짧은 마무리
   (읽은 사람이 해 볼 만한 것 하나).
7. **사진** 5~15장, 2~3문단마다 `[사진 파일이름]`. 가게 위치는 `[장소 가게 정식 이름]` 1개.
8. **길이**: 공백 포함 1,500~2,500자.
